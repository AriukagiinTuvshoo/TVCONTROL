## 2. Шилжүүлгийн найдвартай байдлын архитектур ба шийдлүүд

### 2.1. PostgreSQL Session Advisory Lock (`pg_try_advisory_lock`)
- **Асуудал:** Kubernetes, Cloud Run эсвэл олон VM дээр нэгэн зэрэг ассан backend instance бүр migration эхлүүлбэл хүснэгт түгжигдэх, эсвэл `schema_migrations` хүснэгтэд зөрчилтэй бичилт хийгдэх эрсдэлтэй байсан.
- **Шийдэл:** 64-битийн тусгай advisory lock түлхүүр (`0x46414D5343524E01` буюу `5062400588665038337`) ашиглан session түвшний `SELECT pg_try_advisory_lock(:lock_id)` механизмыг хэрэгжүүлэв.
- **Timeout ба Polling:** Шилжүүлгийн түгжээг авахдаа 100ms-ийн завсартай шалгаж, 30 секундын дотор түгжээ сулрахгүй бол `MigrationLockTimeoutError` үүсгэн аюулгүй зогсоно.
- **Цэвэрлэгээ:** Шилжүүлэг амжилттай дууссан болон алдаа гарсан аль ч тохиолдолд `finally:` блокоор `SELECT pg_advisory_unlock(:lock_id)` хийгдэн түгжээг найдвартай суллана.

### 2.2. SQLite хөгжүүлэлтийн орчны аюулгүй байдал
- Local болон unit test орчинд SQLite ашиглагдах үед `threading.RLock()` ашиглан нэг процесс доторх multi-thread race condition-оос бүрэн сэргийлэв.
- Мөн файлын түвшний түгжээний гацалтаас сэргийлж `PRAGMA busy_timeout = 30000` (30 секунд) тохируулсан.

### 2.3. Transaction Atomicity & Rollback Integrity
- Шилжүүлгийн алхам (DDL/DML) болон хувилбар тэмдэглэл (`schema_migrations`-д бичих/устгах) нэг транзакц дотор хийгдэнэ.
- Алхам дундуур ямар нэг алдаа гарвал өөрчлөлтийг бүтнээр нь `ROLLBACK` хийж, систем хагас хувилбартай үлдэхээс 100% сэргийлнэ.

### 2.4. Хуучин өгөгдлийн бүрэн бүтэн байдал (Data Preservation)
- `users`, `families`, `family_members`, `devices`, `policies` хүснэгтүүд дэх хэрэглэгчийн одоогийн өгөгдөл, гадаад түлхүүрүүд (FK relations), бодлогын тохиргоонуудыг migration хийх явцад 100% хадгална.
- Шинээр нэмэгдсэн `supabase_sub` багана нь `NULL`-ийг зөвшөөрөх ба partial unique index (`WHERE supabase_sub IS NOT NULL`) ашигласнаар одоогийн хэрэглэгчдийн эрх, нэвтрэлтэд ямар ч саад учруулахгүй.

### 2.5. Startup Configuration & Production Guardrails
- **`FAMILYSCREEN_SKIP_STARTUP_MIGRATIONS`:** Production орчинд backend app асах бүрт migration ажиллуулахгүй байх горимыг дэмжинэ (`export FAMILYSCREEN_SKIP_STARTUP_MIGRATIONS=true`). Ингэснээр CI/CD pipeline эсвэл Kubernetes `initContainer`-аас CLI ашиглан migration-ийг тусад нь эрсдэлгүй гүйцэтгэх боломжтой:
  ```bash
  python -m app.migrations           # Бүх шинэ шилжүүлгийг ажиллуулах
  python -m app.migrations --status  # Хийгдсэн шилжүүлгүүдийн төлвийг харах
  python -m app.migrations --rollback # Сүүлийн шилжүүлгийг буцаах
  ```
- **Production SQLite анхааруулга:** `ENVIRONMENT=production` болон SQLite өгөгдлийн сан заагдсан үед систем log дээр CRITICAL анхааруулга өгч, managed PostgreSQL (Supabase, Cloud SQL г.м) ашиглахыг шаардана.
- **Connection Pool Timeout:** `DB_POOL_TIMEOUT` (default: 30s), `DB_POOL_SIZE` (default: 10), `DB_MAX_OVERFLOW` (default: 20) тохиргоог нэмсэн.
