## 1. Ерөнхий Дүгнэлт ба Зорилго (Executive Summary)

Энэхүү аудитын зорилго нь FamilyScreen-ийн Android TV Box дээр ажиллаж буй **агуулгын хяналт (foreground app detection)** болон **хориглох механизм (enforcement logic)** бодит байдал дээр найдвартай ажиллаж чадах эсэхийг эх кодын түвшинд нарийвчлан шалгахад оршино.

> [!CAUTION]
> **ШҮҮМЖЛЭЛТ АЛДАА: ОДООГИЙН ХЯНАЛТЫН КОД НЬ ХОРИОТОЙ АПП-ИЙГ НАЙДВАРТАЙ БАРИХ БОЛОМЖГҮЙ БҮТЭЦТЭЙ БАЙНА**  
> `UsageMonitoringService.kt`-д ашиглаж буй `queryUsageStats(INTERVAL_DAILY, ...)` нь бодит цагийн (real-time) foreground төлөвийг тодорхойлох API биш бөгөөд 24 цагийн нэгтгэсэн түүхэн өгөгдөл буцаадаг. Түүнчлэн `val fgPackage = resolveForegroundPackage() ?: activeSessionPackage` гэсэн fallback логик нь хориотой апп нээгдсэн үед өмнөх зөвшөөрөгдсөн аппыг (жишээ нь YouTube Kids) хэвээр үлдээж, хориглох үйлдлийг бүрэн алгасдаг (false negative) ноцтой цоорхойтой байна.

## 3. Foreground Апп Илрүүлэлтийн Шүүмжлэлт Шинжилгээ

### 3.1. `queryUsageStats()` vs `queryEvents()`-ийн суурь ялгаа
Одоогийн код (`UsageMonitoringService.kt` мөр 259–266):
```kotlin
private fun resolveForegroundPackage(): String? {
    val usm = getSystemService(Context.USAGE_STATS_SERVICE) as? UsageStatsManager ?: return null
    val end = System.currentTimeMillis()
    val start = end - 10_000L
    val stats = usm.queryUsageStats(UsageStatsManager.INTERVAL_DAILY, start, end)
    if (stats.isNullOrEmpty()) return null
    return stats.maxByOrNull { it.lastTimeUsed }?.packageName
}
```

#### Асуулт 1: Одоогийн хэрэгжүүлэлт одоо урд ажиллаж буй аппыг бодитоор тодорхойлж чадаж байгаа юу?
**ҮГҮЙ.**  
- `lastTimeUsed` нь тухайн өдрийн интервал дотор уг апп хамгийн сүүлд хэзээ ажилласан түүхэн timestamp юм.
- Апп дэлгэц дээр одоо *идэвхтэй нээлттэй байгаа эсэх*, эсвэл *хэдийнээ далд орсон/хаагдсан эсэхийг* `UsageStats` огт илэрхийлдэггүй. Жишээ нь хүүхэд өглөө YouTube Kids үзээд хаасан байхад үдээс хойш өөр жижиг апп нээхэд систем YouTube Kids-ийн өглөөний том `lastTimeUsed`-ийг хамгийн сүүлийнх гэж андуурах эрсдэлтэй.

#### Асуулт 2: `INTERVAL_DAILY` өгөгдлийг real-time төлөв гэж үзэж байгаа нь алдаа мөн үү?
**ТИЙМ, МАШ ТОМ АРХИТЕКТУРЫН АЛДАА.**  
- Google Android баримт бичигт: *"The statistics may not be up to date and can lag behind by a few minutes or more... The system may aggregate statistics over an interval larger than requested."*
- `INTERVAL_DAILY` нь өдрийн нийлбэр дүнг хадгалдаг сав (bucket) бөгөөд үйлдлийн систем түүнийг диск рүү цаг тутам эсвэл тодорхой хугацааны дараа цуглуулж (flush) бичдэг. 10 секундын цонхоор `INTERVAL_DAILY` хүснэгтийг асуух нь бодит цагийн төлөвийг өгөх ямар ч баталгаагүй.

#### Асуулт 3: Android API 26–35-д ямар Event-үүдийг ашиглах ёстой вэ?
Foreground шилжилтийг албан ёсоор хянахын тулд `UsageStatsManager.queryEvents(beginTime, endTime)` ашиглан `UsageEvents.Event`-ийг шүүх шаардлагатай:
- **`UsageEvents.Event.ACTIVITY_RESUMED`** (API 29+, integer value `1`): Аппын Activity дэлгэц дээр гарч урд талд ирсэн төлөв.
- **`UsageEvents.Event.MOVE_TO_FOREGROUND`** (API 21–28, integer value `1`): API 29-өөс өмнөх хувилбаруудын ижил утгатай тогтмол.
- **`UsageEvents.Event.ACTIVITY_PAUSED`** (API 29+, integer value `2`): Activity арын төлөвт орсон.
- **`UsageEvents.Event.MOVE_TO_BACKGROUND`** (API 21–28, integer value `2`): Хуучин хувилбарын ижил тогтмол.
- **`UsageEvents.Event.ACTIVITY_STOPPED`** (API 29+, integer value `23`).

#### Асуулт 4: API хувилбарын ялгааг кодонд тооцсон уу?
**ҮГҮЙ.** Кодонд ямар ч SDK хувилбарын шалгалт (`Build.VERSION.SDK_INT`) байхгүй, API 26-аас API 35 хүртэл бүгдэд нь сохоор `queryUsageStats(INTERVAL_DAILY, ...)` дуудаж байна.

#### Асуулт 5: Системийн цонх, Dialog, Олон Activity шилжилтийг хэрхэн зохицуулсан бэ?
**ОГТ ЗОХИЦУУЛААГҮЙ БӨГӨӨД ДАРААХ СӨРӨГ ҮР ДАГАВАРТАЙ:**
1. **Системийн UI (System UI) таслалт:** Android TV-ийн Дууны тохируулга (Volume Panel), Wi-Fi холболтын цонх, эсвэл Гар (Virtual Keyboard/IME) нь `com.android.systemui` эсвэл `com.android.inputmethod` багцад харьяалагддаг.
2. Эдгээр багцууд нь FamilyScreen-ийн `allowedApps` жагсаалтад байхгүй тул хэрэглэгч дуу чангалах эсвэл Wi-Fi тохируулах гэж оролдох төдийд FamilyScreen түүнийг "Хориотой апп нээгдлээ" гэж үзэн Home Launcher-ийг дээш нь татаж **системийн цонхыг хүчээр хаах ноцтой гажиг үүснэ.**

#### Асуулт 6: Өгөгдөл хоцрох, Null ирэх үеийн Fallback-ийн цоорхой (The Fallback Bug)
`UsageMonitoringService.kt` мөр 60:
```kotlin
val fgPackage = resolveForegroundPackage() ?: activeSessionPackage
```
- Хэрэв хүүхэд хориотой апп (жишээ нь Браузер эсвэл Тоглоом) нээхэд `queryUsageStats` хоосон жагсаалт буцаавал `resolveForegroundPackage()` нь `null` буцаана.
- Систем түүний оронд өмнөх зөвшөөрөгдсөн `activeSessionPackage` (YouTube Kids)-ийг хуулж авна!
- Үүний улмаас `timeEngine.isPackageAllowed(fgPackage)` нь **үнэн (true)** гарч, `unauthorizedAppOpen` нь **худал (false)** болно!
- **Үр дагавар:** Хориотой апп дэлгэц дээр бүтэн гарчихсан байхад FamilyScreen түүнийг хэзээ ч хаахгүй, харин ч YouTube Kids-ийн үзэх хугацааг ард нь тоолуурдуулаад гүйлгэсээр байна.

#### Асуулт 7: Зөвшөөрөгдсөн аппыг андуурч хаах (False Positive), Хориотой аппыг алдах (False Negative) эрсдэл бий юу?
**ТИЙМ, ХОЁУЛАА БОДИТОЙ БАЙНА.**
- **False Negative (Хориотойг алдах):** Дээр тайлбарласан Fallback Bug болон `INTERVAL_DAILY`-ийн хоцрогдлоос болж хориотой аппууд бүрэн хамгаалалтгүй нээгдэнэ.
- **False Positive (Зөвшөөрөгдсөнийг хаах):** Системийн dialog, оролтын гар, эсвэл Launcher руу буцах үеийн түүхэн timestamp-ийн зөрүүнээс болж Launcher өөрөө өөрийгөө давтан татаж дэлгэц анивчих (flicker) гажиг үүснэ.

## 4. Enforcement (Хориглох Үйлдэл) ба Lifecycle Согогууд

### 4.1. `FamilyScreenLauncherActivity`-ийн `onNewIntent` Алдаа
`UsageMonitoringService.kt` нь хориглох үедээ дараах тушаалыг өгдөг (мөр 268–274):
```kotlin
private fun bringLauncherToFront(blockReason: String) {
    val launchIntent = Intent(this, FamilyScreenLauncherActivity::class.java).apply {
        addFlags(Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_CLEAR_TOP)
        putExtra("EXTRA_BLOCK_REASON", blockReason)
    }
    startActivity(launchIntent)
}
```
Гэтэл `FamilyScreenLauncherActivity.kt`-ийн бодит код дээр:
- `launchMode="singleTask"` (Manifest L.40) тул Launcher нэгэнт ажиллаж байгаа үед `onCreate()` биш `onNewIntent()` дуудагддаг.
- `FamilyScreenLauncherActivity.kt` мөр 315–326 дээр `onNewIntent()`-ийг харвал:
```kotlin
override fun onNewIntent(intent: Intent?) {
    super.onNewIntent(intent)
    setIntent(intent)
    intent?.getStringExtra("EXTRA_BACKEND_URL")?.let { customUrl ->
        // ... зөвхөн backend url тохируулах логик байна!
    }
}
```
> **ИЛЭРСЭН АЛДАА:** `onNewIntent()` дотор **`EXTRA_BLOCK_REASON`-ийг огт шалгадаггүй, уншдаггүй!**  
> Launcher дээш гарч ирсэн ч хориглосон шалтгаан (жишээ нь "Энэ апп зөвшөөрөгдөөгүй байна") хэрэглэгчид харагдахгүй, харин тухайн өдрийн дэлгэцийн цаг дуусаагүй л бол `LocalTimeEngine` нь `ScreenTimeState.ALLOW` ("Төлөв: ALLOW — Зөвшөөрөгдсөн аппуудыг үзэх боломжтой") гэж ташаа мэдээлнэ.

### 4.2. Polling Давтамж ба Takeover Хоцрогдол
- `monitorRunnable` нь 1000ms (1 секунд) тутам `postDelayed` хийдэг.
- Гэвч UI thread ачаалалтай үед, эсвэл `UsageStatsManager` IPC дуудлага хийгдэхэд уг цикл 1.5–2.5 секунд хүртэл сунадаг.
- Хүүхэд удирдлагын товчоор хориотой апп руу шилжихэд тухайн апп телевизийн дэлгэц дээр **1.0-ээс 3.0 секунд хүртэл тод харагдаж байж** сая нэг Launcher дээшээ татагдана. Бодит хэмжилт хийхээс нааш "0.5 сек takeover" гэж амлах нь ташаа юм.

## 5. Foreground Service ба Android 14 Түвшний Аюулгүй Байдал

### 5.1. `FOREGROUND_SERVICE_TYPE_SPECIAL_USE` Шинжилгээ
- `AndroidManifest.xml` мөр 56–60 дээр Android 14 (API 34) шаардлага хангагдсан байна:
  - `android:foregroundServiceType="specialUse"`
  - `android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE` тохируулагдсан.
- **Хязгаарлалт:** Google Play Store-д уг аппыг оруулах үед `specialUse` төрөл нь Google-ийн гараар хийх шалгалтад (Manual Review) ордог бөгөөд яагаад өөр төрөл ашиглаагүй болохыг баримтжуулахыг шаарддаг. Хэрэглээний TV Box-д шууд суулгах (Sideload / Private distribution) үед энэ нь асуудал үүсгэхгүй.

### 5.2. `BootPolicyRestoreReceiver` Ажиллагаа
- `BOOT_COMPLETED` хүлээн авмагц `startForegroundService` дууддаг нь зөв.
- Android 8.0+ дээр `startForegroundService` дуудсанаас хойш 5 секундын дотор Notification үүсгэж `startForeground()` дуудахгүй бол систем `ForegroundServiceDidNotStartInTimeException` шидэж аппыг унтраадаг.
- `UsageMonitoringService.kt` нь `onCreate()` дээрээ шууд `startForegroundServiceInternal()` дуудаж байгаа тул энэхүү 5 секундын хязгаарлалтад найдвартай багтаж байна.

### 5.3. OEM Background Cleaner-ийн Эрсдэл
- AOSP суурьтай хямд Android TV Box-ууд (Amlogic, Rockchip) нь "Memory Booster" эсвэл "App Killer" програмуудтай ирдэг.
- Эдгээр нь `START_STICKY` байсан ч үл харгалзан Foreground Service-ийг алж болзошгүй тул төхөөрөмж дээр шалгах шаардлагатай.

## 7. Санал Болгож Буй Архитектурын Засвар (Recommended Refactoring)

Phase 10.8-д Standard Mode-ийн хяналтыг бодитоор найдвартай болгохын тулд дараах 4 засварыг хийхийг зөвлөж байна:

### 1. `resolveForegroundPackage()`-ийг `queryEvents()` руу шилжүүлэх
```kotlin
private fun resolveForegroundPackage(): String? {
    val usm = getSystemService(Context.USAGE_STATS_SERVICE) as? UsageStatsManager ?: return null
    val end = System.currentTimeMillis()
    val start = end - 15_000L // 15 секундын гулсах цонх

    val usageEvents = try {
        usm.queryEvents(start, end)
    } catch (_: Exception) {
        return null
    } ?: return null

    val event = UsageEvents.Event()
    var lastResumedPkg: String? = null
    var lastTimestamp = 0L

    while (usageEvents.hasNextEvent()) {
        usageEvents.getNextEvent(event)
        val isResume = if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.Q) {
            event.eventType == UsageEvents.Event.ACTIVITY_RESUMED
        } else {
            @Suppress("DEPRECATION")
            event.eventType == UsageEvents.Event.MOVE_TO_FOREGROUND
        }

        if (isResume && event.timeStamp >= lastTimestamp) {
            lastResumedPkg = event.packageName
            lastTimestamp = event.timeStamp
        }
    }
    return lastResumedPkg
}
```

### 2. Системийн Багцуудын Чөлөөлөлт (System UI Exemption List)
ТВ-ийн тохиргоо, дуу, гарын цонхыг хаахгүйн тулд системийн багцуудыг шалгалтаас чөлөөлөх:
```kotlin
private val SYSTEM_EXEMPT_PACKAGES = setOf(
    "com.android.systemui",
    "com.android.inputmethod.latin",
    "com.google.android.inputmethod.latin",
    "com.google.android.katniss" // Android TV Voice Assistant
)
```

### 3. The Fallback Bug-ийг Засах
Хэрэв `resolveForegroundPackage()` нь `null` буцаавал түүнийг сохоор `activeSessionPackage` болгож хуурахгүй, харин хандалтын эрх шалгах эсвэл Launcher өөрөө урд байгаа эсэхийг тооцоолох.

### 4. `FamilyScreenLauncherActivity`-ийн `onNewIntent`-ийг засах
`EXTRA_BLOCK_REASON` хүлээн авч дэлгэц дээр "ХОРИГЛОГДЛОО: Энэ апп зөвшөөрөгдөөгүй байна" гэсэн улаан анхааруулгыг бодитоор харуулах.
